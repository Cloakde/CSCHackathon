# ADR 0013 — Separate bounded live rehearsal from the ordinary demo

Status: implementation candidate, 2026-09-15. Authorized scope: TASK-308. Acceptance remains pending.

The Chrome side panel remains the in-class product. Ordinary `extension/dist` builds keep capture disabled and permit only the local service in their connection policy. `vite build --mode live-test` produces a separately named `dist-live-test` package that permits the ElevenLabs socket. Even that package opens in Simulation Mode and requires an explicit Live selection, temporary run code, disclosure/consent and second toolbar click on the same tab. No permanent key enters either package.

The existing direct audible source-to-destination connection remains. A separate AudioWorklet tap averages channels and emits bounded Float32 frames; its output is silent. At most two frames can wait for acknowledgements. Overflow, invalid audio or processor failure ends the test. The tested resampler and packetizer deliver contiguous 16 kHz PCM16LE packets of 200 ms. PCM stays transient inside the offscreen document; Chrome messages contain validated transcript events, lifecycle data and the one-run capability only. Timestamps remain those derived by the transport from captured sample offsets; no duration is guessed from words. The offset origin is the start of the tap. Unsent startup audio is not replayed, and a final incomplete passage can be omitted when stopping.

The offscreen transport owner has a 90-second audio/wall limit, up to two token issuances/connections and one reconnect. Terminal transport errors and retention warnings stop capture too; a retryable interruption may use the bounded reconnect. Before consent can arm an integrated capture, the offscreen document must acknowledge a capture lease. The panel sends a one-second heartbeat from consent onward; losing it stops the owner within six seconds, including during delayed media acquisition. Late media is stopped without activating. The independent capture-only spike still survives panel closure as before. Integrated rehearsal deliberately stops on closure because transcript upload belongs to that panel; it cannot silently keep recording while there is no uploader. Reopening starts a new explicit session, not a fake restoration. Service worker reconciliation and generation checks remain in the capture controller. A `stopped` acknowledgement now also closes an armed or active controller record, so offscreen expiry clears the badge.

Live session ingestion is explicitly gated by `LIVELECTURE_LIVE_TEST=synthetic-90-seconds`; ordinary launchers erase that setting. It accepts canonical-schema chunks with stable session/sequence identity, a 90-second offset ceiling and bounded count. Simulation still requires the exact fixture. Lecture tools have an explicit source mode and validate citation text, IDs and timestamps against committed chunks. Live application help/practice can use concepts outside the frozen trial taxonomy, with separate generation/verification and unchanged durable Gemini accounting. Frozen benchmark prompts, schemas, answers and policy IDs are unchanged. Local live input remains synthetic-only until separately approved.

MeltingPot accepts completed validated sessions of either source mode and shows the mode. It forwards only validated assistance-status values, keeps errors honest, and preserves the existing private, local, expiring session boundary. It now remains the requested Finish destination for Gemini too. Bookmarks and source notes are page-local; download is an explicit export, not durable server storage or an AI summary. No inherited MeltingPot model, database, account or shared-Pot path is enabled.

`scripts/manual/live-rehearsal.mjs` is a prepared, unexecuted operator tool. It defaults to a plan without reading keys. Execution needs explicit synthetic/90-second/$1 Scribe flags and the clean reviewed tree plus extension ID. Gemini needs separate explicit flags using the existing shared $1 ledger. A durable whole-dollar Scribe reservation prevents automatic allowance renewal on restart; never remove that record merely to retry. The run code is a temporary file in the Git directory, removed on normal shutdown; it is never printed as a value or committed. The server is loopback-only, the run closes after five minutes, and no browser opens automatically.

This is a local feasibility setup, not production authentication or a full-length lecture release. Fake-transport tests cannot prove audible playback, Chrome lifecycle, speech quality, provider compatibility or retention. Follow the manual acceptance card before enabling or advertising live capture.
